# Design System: Russel Buisan portfolio

## Overview

**Creative North Star: "The Project Showcase"**

Bold typography and compact project identities give the work an immediate presence. Cool page fields, one blue accent, and genuine logos or native name marks connect the expressive portfolio to its quieter technical reading surfaces. The lowercase `russel buisan` wordmark identifies the header; the full name remains in biographical content and metadata, and the portrait remains in About.

The system pairs open reading space and thin rules with purposeful tonal panels and softly lifted logo tiles. Motion acknowledges entry, selection, and pointer attention; content is visible before enhancement and keyboard interaction takes priority. The homepage composition belongs to `.impeccable/surfaces/index-html.md`; its three-line statement and staggered wall are an approved surface expression, not a template for every route. The ATS CV retains a separate print system.

**Key Characteristics:**

- Cool neutrals and one blue accent with equivalent light and dark roles.
- Large Space Grotesk statements, compact project titles, and DM Sans reading text.
- Equal project identities, genuine attributed marks, and optional supporting evidence.
- Open reading layouts, grouped skills, native disclosures, and bounded motion.

## Colors

A cool off-white or charcoal ground supports blue emphasis and quiet reading surfaces.

### Primary

- **Action Blue** (`accent`): primary actions, links, the wordmark surname and browser icon, focus outlines, selected headline words, and current navigation. The dark counterpart is lighter for the charcoal ground.
- **Action Blue Hover** (`accent-hover`): filled-button pointer feedback.
- **Soft Blue** (`accent-soft`): project-identity backings, the research panel, disclosure/filter hover, and the no-script notice.
- **On Blue** (`on-accent`): type on filled blue controls and selected text.

### Neutral

- **Cool Ground** (`bg`): page and opaque sticky header; also the text color on selected filters.
- **Paper Surface** (`surface`): lifted logo tiles, skills cells, expanded studies, small inset tags, and the web CV sheet.
- **Inset Surface** (`surface-2`): identity/media enclosures, the facts sidebar, process steps, and secondary-control hover.
- **Heading Ink** (`ink`): headings, strong facts, secondary actions, and the selected-filter fill.
- **Reading Slate** (`text`): body copy and resting navigation.
- **Quiet Slate** (`muted`): captions, technology lists, facts labels, and dates.
- **Divider** (`line`): section rules, grouped-panel separators, and control outlines.
- **Logo Backing** (`logo-backing`): the fixed pale-green backing used for relevant university/business marks and Agapay's name mark. It is an asset accommodation in both themes, not a second interface accent. Its local logo ink stays the light-theme heading ink.

Each `dark-` entry is the dark value of the corresponding CSS property. Shared components keep the same property names in both themes. System preference supplies the initial theme; a stored explicit choice takes precedence. CSS supplies the system-theme fallback without JavaScript. Theme-aware HammerPulse marks and evidence assets swap with the theme.

**The One Accent Rule.** Use blue for interface emphasis; keep reading surfaces and structural divisions neutral. Genuine project artwork and its necessary backing may retain their own colors.

## Typography

**Display Font:** Space Grotesk, with sans-serif fallback. **Body Font:** DM Sans, with sans-serif fallback. Both are self-hosted variable WOFF2 faces, available at weights 400–700 with swap loading.

**Character:** Large, tightly spaced statements establish the portfolio's voice; shorter titles and generous body leading support technical reading. There is no mathematical type scale. The frontmatter names actual roles and responsive variants, not a menu of interchangeable sizes. The only monospace treatment is the native API name mark.

### Hierarchy

- **Display:** the generic page-title role is separate from the homepage statement. The hero uses tighter leading and tracking; its intermediate role applies at 1024–1100px, tablet role at 768–1023px, and mobile role below 768px. The wide hero clamp remains in place through the 1399px layout adjustment.
- **Reading-page displays:** project details and the case collection have their own fluid title roles. The project title keeps the lower endpoint of its clamp on small screens; the case title has a mobile variant. These are compact reading introductions, not screenshot heroes.
- **Headline:** major sections use the shared fluid heading. The thesis and open contact area have scoped headline variants. Detail-section headings use the smaller fixed heading, with a mobile reduction.
- **Title:** project cards, note rows, study summaries, skills disciplines, and reading subheads each retain the hierarchy shown in the frontmatter. Skills begin with a substantial discipline title, followed by a smaller blue tools line, supporting copy, and a project link. There is no above-title label.
- **Body / Lead / Reading:** default paragraphs stop at 68ch; leads and technical text use shorter measures where appropriate. Project summaries use the denser summary role. Small body text remains separate from metadata and decorative logo lettering.
- **Labels / Tags / Captions:** action labels are semibold, navigation is regular, and stack tags are medium-weight muted text. Captions and counts are smaller. Facts and counts use tabular numerals where useful.

**The Header Identity Rule.** Set the header home link as a lowercase `russel buisan` wordmark in Space Grotesk (28px/1.1, -.04em tracking): given name in heading ink at weight 700, surname in accent at weight 400. Stack the DM Sans role (12px/1.25, reading slate) below with a 2px gap. Below 768px, reduce the name to 22px; keep it on one line and the home link at least 44px tall. Use the accessible name `Russel Buisan, home`, with no initials or badge.

The API mark's braces are literal identity text, not a substitute for an interface icon. ### CV typography scopes

The web CV uses the site families with its own compact hierarchy: a name display, section headings (16px), item titles, body text, contacts (12px), and dates/stacks. Its print override reduces the name, section headings (12px), body, item titles, and metadata using the named print roles. Print sizes are not website reading defaults.

The ATS document is intentionally separate: Arial/Helvetica/sans-serif, name (33px, line-height 1), headline (14.8px, 1.25), uppercase section headings (12.4px, weight 800, line-height 1), item titles (12.8px, 1.2), paragraphs (11.3px, 1.42), lists (11px, 1.34), and metadata (10.8px, 1.25). Contact text is 11.6px/1.35 and the summary is 11.6px/1.45. Its screen-only rule at 820px raises regular reading/meta text to 13px and reduces the name to 28px; summary text retains its scoped override. These density choices belong to the single-page A4 CV.

**The Title First Rule.** Start a content group with its actual title. Place tools, attribution, and supporting context below it; decorative name-mark sublines never become above-title labels.

## Layout

The shared shell and header use `min(1504px, calc(100% - 128px))`; the reading shell uses `min(1200px, calc(100% - 128px))`. The subtraction is the total gutter, not a per-side inset. At 1100px and below all three use `calc(100% - 80px)`. Below 768px, content uses a 40px total gutter and the header uses 32px.

Regular sections have 80px vertical padding, reduced to 56px on mobile. The project index begins with a shorter 44px top inset (32px on mobile). The contact area uses 96px vertically on wider screens, then the mobile section rhythm. Reading sections use 36px vertical padding (28px on mobile), separated by rules. The frontmatter spacing steps reflect recurring values rather than an enforced mathematical scale.

### Collection and reading patterns

The homepage project index uses five equal columns, then four at 1399px, three at 1100px, and two below 768px. Below 480px it becomes a single column of compact image-and-copy rows. Every project receives the same card treatment. The approved homepage's asymmetric hero, 3/4/3 wall, stacked tablet composition, and two-column phone wall remain specified in its surface brief.

About pairs the portrait with text. Case-note reading links form compact illustrated rows, with a two-column intermediate layout before stacking. The skills panel uses three columns, two at 1100px, and one below 768px. Thesis and contact use paired columns until mobile; research content remains a semantic ordered process.

Project details pair a reading introduction with a compact identity, followed by a main text column and a 280px facts sidebar. The sidebar tightens to 240px at 1100px; below 768px it becomes a static panel before the reading content. Wider-screen stickiness starts at 108px from the viewport top. Facts are text and semantic definition lists, not a decorative score wall.

The case collection contains ten equal native disclosures in the homepage's order. Summaries align an identity, title/description, category, and toggle; the category column disappears at 1023px. Expanded content uses two reading columns where appropriate and one on mobile. Optional evidence opens within a nested disclosure.

### Navigation and document geometry

The header is sticky and opaque. Anchor scroll padding is 96px, reduced to 84px on mobile. The compact menu begins at 1023px. Current-section navigation follows a reading line just below the header, so a later section does not become active merely because it enters the bottom of the viewport.

The web CV is a 1040px maximum sheet with 40px padding and a 230px sidebar; it stacks below 768px with 24px/20px sheet padding. Its print layout uses A4 with 0.3in/0.4in page margins, a 200px sidebar, and no sheet border or padding. The ATS document separately uses 210mm × 297mm, zero page margins, and print padding of 7mm 9mm 6mm. Preserve its one-page geometry.

## Elevation & Depth

Depth is a hybrid: open reading areas use space and thin rules; grouped content and compact identities use tonal panels; the interactive wall uses soft lift. The opaque header needs no backdrop blur. Navigation is above the page at layer 10 and the focused skip link above navigation at layer 20.

### Shadow vocabulary

- **Tile resting shadow:** `0 14px 36px -20px rgb(19 38 78 / 28%)` gives the wall's small identity surfaces separation from the page.
- **Tile hover shadow:** `0 24px 44px -22px rgb(19 38 78 / 36%)` accompanies the tile's upward pointer response. Both values are root tokens and remain the same in both themes.
- **ATS preview shadow:** `0 18px 48px rgba(17, 24, 39, 0.12)` is local to the paper preview and disappears in print. It is not shared website elevation.

**The Purposeful Depth Rule.** Use lift for interactive project identities and tonal grouping for related facts or tools. Keep long reading text open and let thin rules carry its structure.

## Shapes

Controls and small factual chips use the 8px corner token. Logo tiles, identity frames, the portrait, grouped skills, reading panels, evidence images, and the web CV sheet use 14px corners. The smallest gallery rows return their image frame to the control radius. Borders are generally 1px and use the divider color. The browser icon uses two blue forward strokes, with no initials or enclosing badge.

The project index has no filled outer card. Stack tags remain plain wrapping text there; the sidebar stack and research activity classes use small tonal enclosures. Logo assets are contained, with the tea artwork's existing cover crop retained. The portrait keeps its 4:5 crop. Old 5px/6px screenshot-crop corners are not part of the current web system.

## Components

### Buttons and text links

Primary buttons are blue; secondary buttons are transparent with an outline and heading-ink text. Both use the action-label role, frontmatter padding, and a normal minimum height of 52px. Hero actions have compact responsive padding and a 50px mobile minimum. Utility controls and standalone links retain a 44px minimum target.

Fine-pointer hover changes fill; a press scales buttons and utility controls to .98 unless keyboard focus is visible. Button transforms, backgrounds, and borders transition in 160ms. Inline reading links use thin blue underlines; arrow-ended project actions and note links communicate direction without adding a second nested link.

### Filters and tags

Filters are native buttons with `aria-pressed`; selected filters use heading ink as the fill and page ground as the text. Pointer hover is soft blue, with the selected state retaining its ink fill. The result count is announced politely. Arrow keys, Home, and End move focus without selecting; keyboard activation filters immediately. Pointer filtering preserves position with a 320ms reflow animation. The logo wall always exposes all ten projects.

Technology tags are descriptive text with a wrapping 4px/12px gap. The sidebar variant adds small surface-colored backings. No text-field or input system exists in the shipped site.

### Project identities and entries

Genuine logos or native name marks identify each project. University artwork is attributed to the University of Southern Mindanao and is not claimed as a dedicated ClassVision logo. Identity captions on detail pages distinguish supplied artwork from a project name mark.

A wall tile is a single native link with a compact identity and a visible project name. Pointer hover lifts it by 8px and changes its shadow over 280ms. A project-index entry is a single native link containing an identity frame, title, summary, stack, and action. Hover adds a subtle blue frame wash, shifts/scales the mark, colors the title, and moves its SVG arrow. Equal project treatment is preserved across the wall, index, and case summaries; there is no featured-project variant.

### Notes, skills, and research

## Do's and Don'ts

### Do:

- **Do** reuse semantic light/dark roles and the established Space Grotesk/DM Sans pairing on web surfaces.
- **Do** give project identities equal treatment and retain genuine logo or native name-mark attribution.
- **Do** lead skills and reading groups with an actual title, followed by supporting context.
- **Do** use compact identities, thin rules, semantic facts, and optional evidence to support technical reading.
- **Do** keep native links and disclosures, visible focus, immediate keyboard actions, and a readable motion-free state.
- **Do** preserve the scoped web CV and the ATS CV's separate Arial typography and single-page A4 geometry.

### Don't:

- **Don't** add above-title eyebrows, invented project logos, or a featured-project hierarchy to the collection.
- **Don't** promote the homepage's composition or decorative logo lettering into a mandate for every page.
- **Don't** use entire-system screenshots as default project identity, or present demonstration data as client outcomes.
- **Don't** turn every reading group into a raised card or remove the wall's purposeful soft depth.
- **Don't** apply 9px decorative mark sublines or CV print sizes to essential web reading or controls.
- **Don't** make content visibility depend on animation, or add looping motion, scroll hijacking, or a custom cursor.

Not canonized: stale `eyebrow` fields in project data are not rendered and establish no visual pattern; legacy generated dashboard mockups and obsolete detector exceptions are not design authority. No current above-title label is recorded as a system rule.
